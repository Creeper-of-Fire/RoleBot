# 荣誉系统使用手册

本手册面向管理员（好吧其实通常只是丢给AI助手），覆盖如何通过 Discord 上下发命令修改本服务器的荣誉配置（honor config toml）。
通常只需将本文件和下载的另一个`honor_xxxx.toml`文件丢给AI，然后告诉它你想做什么即可。

## 概述

每个 guild 一份 `honor_{guild_id}.toml`，作为该服务器荣誉配置的"真理之源"。

- **`definitions`**：所有 honor 的基础定义（uuid、name、description、role_id 等）。bot 启动时（以及 `/上传配置` 成功后）会按此列表同步到 SQLite 数据库。
- **`claimable`**：可自助领取的 honor 配置。
- **`anniversary_honor`**：周年纪念的发证规则（按加入时间）。
- **`cup_honor`**：杯赛元配置（哪个频道发通知、@ 哪个管理组）。**杯赛数据本身仍由 `data/cup_honors.json` 管**，两套并存——本 toml 只放元配置。

通过 Discord 命令 `/荣誉头衔丨配置` 下的子命令组操作 toml（下载/上传/查看哈希）。

> ⚠️ **命令路径与文件名强绑定**——本 bot 同时跑着 honor cog 和 complaint cog 等多个 cog，各自的 `/上传配置` 走的是不同的 `filename_pattern`（honor cog 只认 `honor_{guild_id}.toml`、complaint cog 只认 `complaint_{guild_id}.toml`）。**任何一项不匹配都会直接拒绝**（连 suffix 都要是 `.toml`）。
>
> 实操含义：不要把 honor 配置文件拖到 `/投诉 上传配置`、也不要反过来。每次上传前确认：
>
> 1. 走的命令是 `/荣誉头衔丨配置` → `上传配置`，不是其他 cog 的同名命令
> 2. 文件名是 `/荣誉头衔丨配置 下载配置` 给的默认名（含正确的 guild_id）
>
> 这个限制**不是 bug，是故意的安全护栏**——把 A cog 的 toml 拖给 B cog 几乎一定是误操作，bot 拒了比默默吞掉好。

## 字段详解

### `definitions`（array of tables）

```toml
[[definitions]]
uuid = "148d3e7b-7411-437f-adc6-814941cc7aa9"
name = "贞露未晞·幽香自持"
description = "参与2026年百合创作大赛！"
role_id = 1466133175225946246
hidden_until_earned = false
role_sync_honor = false
# icon_url = "https://..."   # TOML 没 null 类型，未设置就省略
```

| 字段                    | 必填 | 类型                   | 说明                                                                                                                                                                             |
|-----------------------|----|----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `uuid`                | ✅  | str                  | 唯一标识（数据库主键）。UUID4 格式；不要重复                                                                                                                                                      |
| `name`                | ✅  | str (1-100)          | 荣誉名                                                                                                                                                                            |
| `description`         | ✅  | str (≤255)           | 描述                                                                                                                                                                             |
| `role_id`             | ❌  | int \| 省略            | 对应 Discord 身份组 ID；**省略 = 无对应身份组的纯粹成就荣誉**——HonorManageView 会显示为 "✨ 纯粹成就荣誉 (无身份组)"。可能是纯头衔、已归档、或设计上就不需要 role。不要置0，直接留空即可。                                                         |
| `hidden_until_earned` | ❌  | bool (default true)  | 未获得时是否在荣誉墙隐藏，通常，对于“当前可人人获取”的荣誉——一般只指“自助领取荣誉”，建议设置为false，以起到宣传活动的作用，其他情况都建议设置为true，不患寡而患不均嘛                                                                                     |
| `role_sync_honor`     | ❌  | bool (default false) | `true` 时，在打开荣誉墙时，持有 `role_id` 的成员自动获得此 honor。尽管默认值是false，但是通常建议直接设置为true。对于自助领取身份组和周年身份组，由于其为“本BOT自动授予荣誉——领取对应身份组”的单向流动，所以基于清晰的考虑，设置为false。其他荣誉通常都存在“手动授予身份组——获得对应荣誉”的路径，所以无所谓 |
| `icon_url`            | ❌  | str \| 省略            | 荣誉图标 URL                                                                                                                                                                       |

### `claimable`

可自助领取的 honor 配置。通常用于活动。

```toml
[claimable]
uuids = [
    "148d3e7b-7411-437f-adc6-814941cc7aa9",  # 贞露未晞·幽香自持
    "fc5c3514-47cc-463c-bdb9-3ee7b2656a58",  # 夏日祭观客
]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `uuids` | list of str | 可自助领取的 honor uuid；引用 `definitions` 里某条的 uuid |

### `anniversary_honor`

```toml
[anniversary_honor]
enabled = true

[[anniversary_honor.tiers]]
honor_uuid = "4a661a5d-0e99-4966-8e97-bd00ce20e913"
cutoff_date = "2024-07-30 00:00:00"  # UTC+8，格式 "YYYY-MM-DD HH:MM:SS"
```

| 字段 | 类型 | 说明                                                                                           |
|---|---|----------------------------------------------------------------------------------------------|
| `enabled` | bool | 是否启用周年纪念检查                                                                                   |
| `tiers` | array | 周年等级列表，建议写 toml 时按 cutoff_date 升序以保证整洁，加入时间早于 cutoff_date 的均可获取荣誉，荣誉不互斥（本质上不是真正的tier，只是命名问题） |

`tiers[i].honor_uuid` 必须能在 `definitions` 里找到对应 honor，否则 anniversary_module 跳过该 tier。

### `cup_honor`（元配置，数据走 json）

```toml
[cup_honor]
enabled = true

[cup_honor.notification]
channel_id = 1398638357210202194  # 中层管理办公室
admin_role_id = 1396831061643755520  # 杯赛委员
```

杯赛的荣誉定义存储在 `data/cup_honors.json`，由 “杯赛相关的CURD指令” 维护，本 toml 只放"通知到哪、@ 谁"的元配置，无需存储杯赛相关的荣誉定义/荣誉信息。两套**独立**，删除一个不影响另一个。

## 哈希校验机制

上传 toml 时必须带 hash（SHA-256 前 12 字符）：

- 本地无配置（首次上传）：允许省略 hash，bot 会给二次确认按钮
- 本地有配置：必须带 hash
  - bot 落盘前再次校验 toml 当前磁盘 hash 是否仍以你提供的 hash 开头（write-time check，TOCTOU 安全）
  - 不匹配：拒绝写入（说明你编辑期间被更新，重新 `/下载配置` 再来）

完整 64 字符 hash 也能通过（系统只看前 12 字符做 prefix match）。

## 常用修改场景

### 加一个新的活动身份组

1. 用任何方式生成一个 UUID4（在线 UUID 生成器、Python、Discord 机器人命令等；只要是合法的 uuid4 字符串就行，别用占位符或与已有重复——只要你随机重新生成了一个uuid4，且使用合格的高质量熵源，理论上都不会重复，无需多虑）
2. `/下载配置` 拿 toml
3. 在 `[[definitions]]` 末尾追加新条目
4. 在 `[claimable].uuids` / `anniversary_honor.tiers` 等地方按需引用
5. `/上传配置`，粘上 hash

### 加周年纪念 tier

1. 生成新 UUID
2. 在 `[[definitions]]` 末尾加新条目（`role_id` 是否填看你需要可佩戴身份组还是纯成就荣誉，也可先留空）
3. 在 `[[anniversary_honor.tiers]]` 末尾加新 tier，指向新 uuid
4. 上传

## 注意事项

- **不要在 toml 里写 `null`**：TOML 标准无 null 类型，省略即可；pydantic load 时会取 `Optional` 字段的默认值（None）。
- **uuid 改了等于换条新 honor**：原 uuid 会被标记 `is_archived=True`（旧数据保留在 DB，但 UI 不再显示已归档的）。如果只是小调整（描述、role_id 之类），改原条目即可，不要改 uuid。如果不小心改了/删了，导致旧荣誉归档，只需加回去即可自动转为未归档。
- **删除 definition 不会丢数据**：toml 移除某条目后，bot 同步时把对应 DB 记录标记 `is_archived=True`，保留历史。
- **不需要重启 bot**：`/上传配置` 成功后会自动调 `HonorCog.synchronize_all_honor_definitions()` 同步到 SQLite，运行中的 bot 立刻看到新条目。
- **回滚**：CoreCog 每 12 小时把 `data/` 打成 zip 发到 `BACKUP_CHANNEL_ID` 频道；历史 toml 在那些备份附件里。

## 常见问题

**Q: 上传时报"哈希前缀不匹配"？**
A: 大概率是你编辑期间别人上传了新版。重新 `/下载配置` 拿最新 hash，再编辑，再上传。

**Q: 上传时报"文件名校验"失败？**
A: 通常是两个原因之一：

1. **走错了 cog 的上传入口**——honor / 投诉 / 未来其他 cog 都各自有 `/上传配置`，每个 cog 只接受自己 `filename_pattern` 命名的文件。请确认你走的是 `/荣誉头衔丨配置` 而不是别的 cog。
2. **文件被改名了**——bot 严格按 `honor_{guild_id}.toml` 校验前后缀，任何改名（哪怕只是大小写、多余字符）都会被拒。保留 `/下载配置` 给的默认文件名即可，不要重命名。

**bot 不会做跨 cog 的"宽容匹配"——这不是 bug，是防呆**：误把 A cog 的 toml 拖进 B cog 会污染配置，严格拒绝更安全。
